## 1. Анализ монолитного приложения и планирование микросервисной архитектуры

### 1.1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут включать/выключать (turnOn/turnOff) различные подсистемы отопления HeatingSystem по их id,    
  устанавливать желаемую температуру (targetTemperature) в различных подсистемах отопления;
- Система позволяет устанавливать температуру в различных подсистемах отопления (updateHeatingSystem);

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру (currentTemperature) в различных подсистемах отопления
  HeatingSystem по их id;
- Система позволяет получить температуру с датчиков (TemperatureSensor) для различных подсистем отопления (
  HeatingSystem);

### 1.2. Анализ архитектуры монолитного приложения

Монолитное приложение является REST-сервисом, написанном на языке Java 17 с использованием Spring Framework,  
с синхронным API на основе HTTP-протокола, с хранением данных в базе PostgreSQL.  

### 1.3. Определение доменов и границ контекстов

В монолитном приложении можно выделить следующие **домены** по функциям и процессам:  
- Управление устройствами подсистем отопления;   
- Мониторинг подсистем отопления (телеметрия);  

В домене "Управление устройствами подсистем отопления" можно выделить единый **контекст**:  
- включения/выключения подсистем отопления с регулированием температуры; 

В домене "Мониторинг подсистем отопления" можно выделить два **контекста**:   
- мониторинг подсистем отопления, включая мониторинг настроек и мониторинг текущей температуры;  
- сбор данных с температурных датчиков для подсистем отопления;  

### 1.4. Проблемы монолитного приложения

В архитектуре монолитного приложения можно выделить следующие проблемы:   
- сложность масштабирования отдельных компонентов приложения в случае увеличения нагрузки;   
- тесная взаимосвязь различных бизнес-функций и отсутствие автономности;    
- проблемы с устойчивостью к отказам по причине того, что отказ одного компонента приводит к отказу всего сервиса;   
- сложности в разработке, тестировании и развертывании различных компонентов сервиса;

## 2. Проектирование микросервисной архитектуры

Перевод монолитного приложения на микросервисную архитектуру решает указанные выше проблемы.  
Микросервисы сформированы по выделенным доменам в монолитном приложении.  
Применен паттерн CQRS: разделены операции чтения (через smart-home-telemetry) и записи (через smart-home-devices) по разным интерфейсам.
